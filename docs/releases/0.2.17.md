# AT Terminal 0.2.17 Release Notes

## Summary

Version 0.2.17 combines **MCP security/bridge hardening** with **per-server background connection authorization** for agent-window IDEs. AT Terminal can act as a service host and asset manager while agents call authorized SSH targets through MCP without keeping an interactive terminal open.

## Highlights

- **Allow background connections**: opt-in per server so MCP can list and run remote commands against that host in the background.
- **Agent-window ready**: IDE focuses on assets, secrets, trust policy, and the local MCP bridge; the agent window drives operations.
- **Security hardening**: real SFTP write authorization, host-key checks on SFTP, bridge body validation/size limits, multi-window bridge discovery.

## Added

- Server setting `backgroundConnectionAllowed` (default off / deny for legacy configs).
- Server form control **Allow background connections**, nested under **Trust agent remote commands**.
- MCP gating:
  - `list_ssh_servers` returns only authorized servers.
  - `run_remote_command` rejects unauthorized servers (including active terminal targets).
- Jump Host fields moved into a dedicated panel under Authentication (side-by-side Group / Server).
- Skill/docs wording for authorized background servers.

## Fixed / Improved

- Restores production `SftpWriteAuthorizer` so agent SFTP writes prompt for first-write authorization per server.
- Passes host key verification into UI and agent `SftpSession` connections (aligned with interactive SSH terminals).
- Validates MCP bridge tool request bodies with Zod and returns HTTP 400 on schema failures.
- Caps MCP bridge HTTP request bodies at 2 MiB (HTTP 413 when exceeded).
- Registers per-window bridges under `~/.at-terminal/mcp-bridges/` while keeping `mcp-bridge.json` as a last-writer compatibility snapshot.
- `BridgeClient` prefers a healthy bridge that reports non-empty `connectedTerminals`.
- Aligns stdio MCP server version with the extension package version.
- Exposes `sshManager.idleDisconnectMinutes` in extension configuration (default 60, `0` disables).
- Hides the inline SSH Connect action on server tree rows (Connect remains available elsewhere).
- Trust parent constraint: background connection cannot stay enabled when trust is off (form save + UI).
