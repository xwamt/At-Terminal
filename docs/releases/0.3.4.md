# AT Terminal 0.3.4 Release Notes

Version 0.3.4 introduces a complete overhaul of the remote command confirmation security engine by integrating the Tree-sitter AST-based `@at-series/command-policy` runtime, adds live synchronization of SSH server configuration updates across active terminal sessions, and delivers packaging optimizations for WebAssembly policy assets.

## Highlights & New Features

### 1. AST-Based Remote Command Policy Engine (`@at-series/command-policy`)
- **Semantic AST Evaluation**: Replaced the previous naive lexer and hard-coded command name blocklist with the AST-driven policy evaluator (`@at-series/command-policy@0.1.0`).
- **Proven Read-Only Execution**: Under Limited Trust mode, commands automatically bypass confirmation prompts only when the evaluator formally proves the execution is an ordinary read (`action: allow`).
- **Structured Reason Codes & Risk Summaries**: Commands requiring user confirmation (`action: review` or `action: deny`) return structured `reasonCode` and detailed `riskSummaries` evidence.
- **Deep Inspection for Complex Payloads**: Quoted multi-line scripts, piped chains, subshells, and static wrappers (such as `sudo`, `python3 -c`, and `sqlite3`) undergo semantic AST inspection instead of blanket name-based blocking.

### 2. Enhanced Confirmation Dialog & UI Feedback
- **Granular Risk Preview in Prompts**: The remote command confirmation modal now renders itemized risk summaries extracted from the AST analysis, ensuring users understand potential side-effects before authorizing execution.
- **Dynamic Server Context Synchronization**: Saving changes to an existing server in the Server Form immediately synchronizes active terminal context instances (`TerminalContextRegistry` and `TerminalPanel`) without requiring manual reconnects.

### 3. Build & Packaging Architecture
- **Policy Runtime & WASM Bundling**: The MCP variant build workflow now compiles `dist/policy-runtime.js` and packages WebAssembly parsers (`web-tree-sitter.wasm`, `tree-sitter-bash.wasm`, `tree-sitter-python.wasm`).
- **Base Variant Isolation**: The Base variant cleanly stubs policy runtime and Hub dependencies to maintain a lightweight footprint.
- **Updated Test Suites**: Comprehensive test coverage across remote command authorization, destructive hints, live context updates, and packaging variants.
