### 3.3 ZGC 三倍映射内存核实 (`pmap` 证据)

通过 `pmap -x 17722`（cl-payment-engine-offline，ZGC，-Xmx6144m）采集到直接证据：

```
Address           Kbytes     RSS   Dirty Mode  Mapping
0000040000000000 5242880 5242880 5242880 rw-s- memfd:java_heap (deleted)   ← 映射 1 (Marked0)
0000080000000000 5242880 5242880 5242880 rw-s- memfd:java_heap (deleted)   ← 映射 2 (Marked1)
0000100000000000 5242880 5242880 5242880 rw-s- memfd:java_heap (deleted)   ← 映射 3 (Remapped)
```

**关键发现**：
1. 同一个 5.0 GiB 的物理堆内存被 ZGC 通过 `memfd_create` 创建后，在虚拟地址空间中映射了 **3 次**。
2. 每次映射的 RSS 均报告为 5,242,880 KB (5.0 GiB)，但这 3 个映射实际**共享同一套物理页帧**。
3. 因此 `ps`、`top`、`docker stats` 等工具对该进程报告的 RSS 约为 **15 GiB**（3 × 5.0 GiB），但**真实物理占用仅为 ~5.0 GiB**。
4. 由于 ZGC 使用 `memfd` 共享内存文件作为堆载体，这 5.0 GiB 的物理页在 `/proc/meminfo` 中被计入 `Shmem`（共享内存）和 `Cached`（页缓存），而不是传统的 `AnonPages`。

| Committed_AS 超额 | 超出 CommitLimit 约 10.38 GiB | 依赖 overcommit 策略；若切换为 overcommit=2 将立即被拒绝 |

### 3.7 G1GC 对照组验证

PID 1162（cl-taskcenter-offline）使用 G1GC，配置 `-Xms2560m -Xmx2560m`。该进程：
* **不使用** `memfd` 共享内存映射，堆内存通过标准匿名页（AnonPages）分配。
* 不会在 `/proc/meminfo` 的 `Shmem` 中计入任何堆开销。
* RSS 报告值即为真实物理占用，无 3 倍膨胀问题。

这是一个天然对照组，说明 **G1GC 可以显著降低系统级 Shmem 压力和 RSS 统计失真**。
